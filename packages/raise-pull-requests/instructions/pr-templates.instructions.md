# Pull Request Template Standards

When creating or editing pull request templates:

- Start with a "Description" section for context on what and why
- Include a "Type of Change" checklist (bug fix, feature, breaking change, docs)
- Add a "Testing" section describing how the change was verified
- Include a self-review checklist for common quality checks
- Add a "Related Issues" section with closing keywords (`Closes #123`)
- Keep the template concise — long templates discourage thorough completion
- Use HTML comments for guidance that should not appear in the final PR
- Include a "Screenshots" section for UI changes (if applicable)
